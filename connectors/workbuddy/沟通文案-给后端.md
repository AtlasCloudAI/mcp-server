# 文案 · 发给后端

> 只剩这一封。给腾讯那封不需要了 —— 动态注册模式下客户端自带回调地址，
> 不用向平台索取任何参数。

---

WorkBuddy（腾讯）连接器要接一键登录，**官网 OIDC 要加 RFC 7591 动态客户端注册。**

先把工作量说清楚，别被「加个端点」骗了：注册端点本身不难，但注册出来的客户端要落库、
跨副本可见、在 refresh_token 有效期内一直可用，**这部分才是主体**。

先说依据，免得像是我们一家的特殊要求。WorkBuddy 市场 236 个连接器里，142 个是远程服务且不让用户填凭证，只能靠 OAuth。抽查五个第三方，授权服务器全部提供动态注册：

- Canva `https://mcp.canva.cn/register`
- 千图网 `https://ai.58pic.com/oauth/register`
- 八爪鱼 `https://identity.bazhuayu.com/connect/register`
- FastMoss `https://mcp.fastmoss.com/oauth/register`
- 分贝通 `https://mcp.fenbeitong.com/register`

原因是 WorkBuddy 桌面端内置官方 MCP TypeScript SDK，缺 `registration_endpoint` 时直接抛
`Incompatible auth server: does not support dynamic client registration`，
而且那个 SDK 版本不实现客户端元数据文档（CIMD），所以我们现有的 CIMD 通道对它无效。

把分贝通的授权服务器和我们逐项对照，差距就一行：

| 字段 | 分贝通 | 我们 |
|---|---|---|
| code_challenge_methods_supported | S256 | S256 ✅ |
| grant_types_supported | code + refresh_token | 同 ✅ |
| token_endpoint_auth_methods_supported | 含 none | 含 none ✅ |
| **registration_endpoint** | **有** | **无** ❌ |

要做三件：

1. **实现并公布动态注册端点。** 路径随意，WorkBuddy 从发现文档读。响应必须原样回显 `redirect_uris`，不要签发 client_secret（公开客户端靠 PKCE）。建议按 IP 限流。
2. **clientRegistry 加第三个来源。** 现在是配置登记 + 元数据文档两路，动态注册的要落库、多副本共享。
3. **边缘网关放行注册路径。** 判据：`/healthz`、`/me` 是真实路由但生产 404，说明外面有路径白名单。

代码位置：AtlasCloudTeam/kubedl，分支 **master**，
`console/backend/pkg/authzserver/metadata.go`（发现文档）、`registry.go`（注册表）、
`console/backend/pkg/routers/api/oidc.go`（端点挂载）。

⚠️ 仓库里 `feat/oidc-provider` 分支（pkg/oidcprovider/）是 2026-08-18 未合并的旧实现，不是生产代码，别照它改。

不用做的：公开客户端已支持、PKCE 已支持、不用向腾讯要任何参数、不用改现有端点路径、MCP server 和生产镜像完全无关。

还有一条本来想提、查完发现不用做的：回环回调不必按 RFC 8252 放开端口匹配。
它的回调服务器确实每次用随机端口（`server.listen(0)`），但客户端在 connect 时
若发现没有 refresh_token，会先作废已注册的 client 再重新注册——凡是真要跳浏览器的时候，
它刚用当前端口注册过，精确匹配就够。

完整规格含验收命令：mcp-server 仓 `connectors/workbuddy/OAuth改造需求-给后端.md`
