# 文案 1 · 发给腾讯 WorkBuddy 团队（要参数）

> 渠道：开放平台首页的开发者社群 / openworkbuddy@tencent.com
> 目的：拿到 oauth_redirect_url 和 client_id

---

你好，我们是 Atlas Cloud（atlascloud.ai），正在提交 MCP 连接器，source 是 `atlas-cloud`。

想申请按 `auth_mode: server-side` 云端托管 OAuth 接入，让用户点「连接」直接用我们官网账号授权，不用手填 API Key。

我们这边已经就绪：

- 远程 MCP 服务已上生产：`https://mcp.atlascloud.ai/mcp`
- 资源元数据：`https://mcp.atlascloud.ai/.well-known/oauth-protected-resource`
- 授权服务器：`https://auth.atlascloud.ai`，OAuth 2.1，支持 PKCE S256、authorization_code + refresh_token、公开与机密客户端、资源指示符

需要贵方提供两个参数，我们登记后即可联调：

1. 回调地址 `oauth_redirect_url`
2. 希望使用的 `client_id`，以及是否需要我们签发 `client_secret`

另外想确认 `oauth_app_name` 的填写要求。

补充说明为什么不走动态注册：贵方桌面端内置的 MCP SDK 在授权服务器没有 `registration_endpoint` 时会抛
`Incompatible auth server: does not support dynamic client registration`，
而我们的授权服务器目前提供预注册与客户端元数据文档两种方式，未开放 RFC 7591。
托管模式对双方都更省事，我们加一条客户端登记即可。

连接器基本信息：Atlas Cloud 媒体生成，300+ 模型的图片 / 视频 / 音频 / 转写生成，12 个 MCP 工具，费用记在用户自己的 Atlas 账户上。

麻烦了，有任何需要我们补充的材料随时说。


# 文案 2 · 发给后端（排期）

> 目的：让后端知道要做什么并排期，参数到位当天就能收尾

---

WorkBuddy（腾讯）连接器要接一键登录，需要官网 OIDC 配合，**只有一条配置，不用写代码**。

背景：WorkBuddy 的云端托管 OAuth 模式下，它的服务端是 OAuth 客户端，用我们预先登记的 client_id 发起授权。
所以不需要实现 RFC 7591 动态注册，就是一次标准的「注册第三方 OAuth 应用」，和接 GitHub 登录同构。

要做的：在官网 OIDC 的客户端配置里加一条预注册客户端

- client_id：WorkBuddy 指定（待对方给）
- client_secret：对方要求机密客户端则签发，公开客户端留空
- redirect_uris：WorkBuddy 的回调地址（待对方给，固定 HTTPS）
- 授权类型：authorization_code + refresh_token
- scope：tasks:read
- 资源：https://mcp.atlascloud.ai/mcp

代码位置：AtlasCloudTeam/kubedl，分支 master，
`console/backend/pkg/authzserver/registry.go` 的 `newClientRegistry` 启动时加载 `config.AuthServerClient` 列表，加一条配置即可。

提醒：仓库里 `feat/oidc-provider` 分支（pkg/oidcprovider/）是 2026-08-18 未合并的旧实现，不是生产代码，别照它改。

现状已满足无需改动：PKCE S256、authorization_code + refresh_token、公开与机密客户端、资源指示符、HTTPS、OAuth 2.1 错误格式。
实测见 https://auth.atlascloud.ai/.well-known/openid-configuration

前置：要等 WorkBuddy 团队给回调地址和 client_id，已在申请中。先排期，参数到了当天能收尾。
