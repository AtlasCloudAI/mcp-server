# MCP Server 生产更新到 v2.6.0

一次滚动更新，改两个地方：换镜像、ConfigMap 加一行。**镜像已经推好了，不用你们构建。**

命名空间 `atlas-mcp`，Deployment `atlas-mcp`（以集群里实际名字为准）。

## 改什么

**一、ConfigMap `atlas-mcp-config` 加一行**

```yaml
MCP_ADVERTISED_SCOPES: "tasks:read,tasks:write,billing:read"
```

**二、镜像换成 v2.6.0**

```
registry.atlascloud.ai/vcv-dg/atlascloud-mcp-openai-plugin:v2.6.0
digest: sha256:86b41f0d741202423c05b2ffb4ca813eaa4a2e11de7ff79e34909a77430fa5ac
```

仓库里 `deploy/kubernetes/production/` 的 `01-configmap.yaml` 和 `04-deployment.yaml`
已经改好了，手上有这个仓库直接 apply 这两个文件也行；没有的话用下面的命令，不需要任何文件。

## 两步都要做，缺一个都不行

| 只改 ConfigMap | 公示了三项权限，但客户端拿不到续期凭证，用户每 15 分钟要重新授权一次 |
| 只换镜像 | 能续期了，但只公示读权限，12 个工具里 8 个（全部生成类）调不动 |

## 命令

先确认资源名和这里写的一致（清单和线上可能有出入）：

```bash
kubectl -n atlas-mcp get deploy atlas-mcp \
  -o jsonpath='{.spec.template.spec.containers[0].name}{"\n"}'
```

应输出 `mcp`。然后：

```bash
kubectl -n atlas-mcp patch configmap atlas-mcp-config --type merge \
  -p '{"data":{"MCP_ADVERTISED_SCOPES":"tasks:read,tasks:write,billing:read"}}'
kubectl -n atlas-mcp set image deploy/atlas-mcp \
  mcp=registry.atlascloud.ai/vcv-dg/atlascloud-mcp-openai-plugin@sha256:86b41f0d741202423c05b2ffb4ca813eaa4a2e11de7ff79e34909a77430fa5ac
kubectl -n atlas-mcp rollout status deploy/atlas-mcp --timeout=180s
```

⚠️ **ConfigMap 改完必须滚动重启才生效** —— 环境变量在 Pod 启动时固化，光 apply 不换 Pod 等于没改。
上面第二条 `set image` 本身会触发滚动，所以按这个顺序执行就够了；如果你们只改 ConfigMap 不换镜像，
要额外 `kubectl -n atlas-mcp rollout restart deploy/atlas-mcp`。

## 做完怎么验（我们这边也会验一遍）

```bash
curl -s https://mcp.atlascloud.ai/.well-known/oauth-protected-resource | jq .scopes_supported
```

没有 `jq` 就用这条，输出一样：

```bash
curl -s https://mcp.atlascloud.ai/.well-known/oauth-protected-resource \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["scopes_supported"])'
```

**期望输出：**

```json
["tasks:read","tasks:write","billing:read","offline_access"]
```

现在是 `["tasks:read"]`。这一条对了就说明两步都生效了 —— 前三项来自 ConfigMap，
`offline_access` 来自新镜像，任何一步漏了这个输出都不完整。

服务健康看 `https://mcp.atlascloud.ai/readyz`，返回 200 即可（自检没过时它会是 503）。

## 回滚

```bash
kubectl -n atlas-mcp set env deploy/atlas-mcp MCP_ADVERTISED_SCOPES="tasks:read"
kubectl -n atlas-mcp set image deploy/atlas-mcp \
  mcp=registry.atlascloud.ai/vcv-dg/atlascloud-mcp-openai-plugin:v2.5.0
kubectl -n atlas-mcp rollout status deploy/atlas-mcp --timeout=180s
```

⚠️ **前两条都要执行**（第三条只是等滚动完成）。**第一条不能写成 `set env ... MCP_ADVERTISED_SCOPES-`。**
这个变量是通过 `envFrom: configMapRef` 从 ConfigMap 注进来的，不在 Deployment 自己的
`env:` 列表里，`VAR-` 删的是后者 —— 删一个不存在的条目是空操作，ConfigMap 的值照样生效。
上面写的是**显式赋值覆盖**：`env:` 的优先级高于 `envFrom`，写进去就盖住 ConfigMap 那份。

彻底回退也可以改 ConfigMap 把那一行删掉再 `rollout restart`，效果一样，多一步。

`kubectl rollout undo` 在这里同样不够 —— 它只回镜像，ConfigMap 不在它的管辖范围内。

## 影响范围

**这次改的是用户授权时申请哪些权限。** 授权页会从一项变成四项，多出来的三项是
「查看用量和消费明细」「替你创建任务」「在你不在场时继续访问」。

- **不影响官网、控制台、API key 调用** —— 那几条路不走这套 OAuth。
- **不影响 Codex** —— 它本来就自己申请 `offline_access`，也允许这几项权限；
  变化只是同意页上多几行。
- **已经授权过的用户不受影响**，他们手上的令牌继续有效；下次重新授权时才会看到新的同意页。

## 顺带一句

今天上午 `auth.atlascloud.ai` 的网关放行规则一度只剩 `/register`，
`/authorize` `/token` `/jwks` `/consent` 全部 404 了一段时间，现在六条都通了。
如果后面还要调那条规则，麻烦确认这六条一个都不少 —— `/jwks` 掉了会让所有已登录用户
在五分钟内陆续掉线，而现象是 401，看起来像「没登录」，很难往网关上想。
