# MCP Server 生产更新到 v2.7.0

一次滚动更新，改三个地方：ConfigMap 加三行、ingress 改一行、换镜像。
**镜像 CI 已经构建好推完了，不用你们构建。**

命名空间 `atlas-mcp`，Deployment `atlas-mcp`，容器 `mcp`（以集群里实际名字为准）。

---

## 改什么

### 一、ConfigMap `atlas-mcp-config` 加三行

```yaml
MCP_UPLOAD_MAX_BYTES: "33554432"
MCP_UPLOAD_TICKET_TTL_SECONDS: "600"
MCP_UPLOAD_REQUESTS_PER_MINUTE: "30"
```

### 二、ingress 的请求体上限：`256k` → `40m`

```yaml
nginx.ingress.kubernetes.io/proxy-body-size: 40m
```

**这一条不改，上传功能必然 413。** 256k 只够放 JSON，新增的上传端点要收整个文件。

### 三、镜像换成 v2.7.0

```
registry.atlascloud.ai/vcv-dg/atlascloud-mcp-openai-plugin:v2.7.0
digest: sha256:c80f1c3397b8e0abc32a46cbf1b6cd3e0e416276fd5a0bf908018c00d2c4a610
```

仓库里 `deploy/kubernetes/production/` 的 `01-configmap.yaml` 和 `05-ingress.yaml` 已经改好，
手上有仓库直接 apply 这两个文件也行；没有的话用下面的命令，不需要任何文件。

---

## 三步都要做，缺一个都不行

| 只换镜像 | 上传端点在，但请求体超过 256k 就被入口 413 —— 除了极小的图，全都传不上去 |
| 只改 ingress | 没有上传端点，改了没用 |
| 只改 ConfigMap | 同上；且这三个变量都有代码默认值，不加也能跑，加是为了让线上配置显式可见 |

## 命令

先确认资源名和这里写的一致：

```bash
kubectl -n atlas-mcp get deploy atlas-mcp \
  -o jsonpath='{.spec.template.spec.containers[0].name}{"\n"}'
```

应输出 `mcp`。然后：

```bash
kubectl -n atlas-mcp patch configmap atlas-mcp-config --type merge -p '{"data":{
  "MCP_UPLOAD_MAX_BYTES":"33554432",
  "MCP_UPLOAD_TICKET_TTL_SECONDS":"600",
  "MCP_UPLOAD_REQUESTS_PER_MINUTE":"30"}}'

kubectl -n atlas-mcp annotate ingress <ingress名> \
  nginx.ingress.kubernetes.io/proxy-body-size=40m --overwrite

kubectl -n atlas-mcp set image deploy/atlas-mcp \
  mcp=registry.atlascloud.ai/vcv-dg/atlascloud-mcp-openai-plugin@sha256:c80f1c3397b8e0abc32a46cbf1b6cd3e0e416276fd5a0bf908018c00d2c4a610

kubectl -n atlas-mcp rollout status deploy/atlas-mcp --timeout=180s
```

⚠️ ConfigMap 改完必须滚动重启才生效（环境变量在 Pod 启动时固化）。
上面 `set image` 本身会触发滚动，按这个顺序执行就够了。

## 做完怎么验（我们这边也会验一遍）

### 1. 上传端点通了

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  "https://mcp.atlascloud.ai/upload/not-a-ticket" \
  -H "X-Atlas-Filename: a.png" --data-binary "x"
```

**期望 `401`。** 现在是 `404`。

- `401` = 成功（请求到达应用，被票据校验拒绝——这正是对的）
- `404` = 镜像没换
- `413` = 镜像换了但 ingress 上限没改

### 2. 请求体上限真的放开了 —— 这条请务必做

```bash
head -c 2097152 /dev/zero > /tmp/2mb.bin
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  "https://mcp.atlascloud.ai/upload/not-a-ticket" \
  -H "X-Atlas-Filename: big.bin" --data-binary @/tmp/2mb.bin
rm -f /tmp/2mb.bin
```

**期望 `401`**（2MB 的请求体到达了应用）。如果是 `413`，说明入口上限没生效。

> **为什么要单独验这条**：生产入口实际是 **Higress（Envoy）**，不是 nginx-ingress。
> 那个 `nginx.ingress.kubernetes.io/...` 注解**在 Higress 上是否生效我们没有验证过**。
> dev 上实测 Higress 默认就放行了 33MB，所以很可能本来就不需要这个注解——但
> 「很可能」不够，请用上面这条命令实测。不生效的现象是用户传稍大的文件就 413，
> 看起来像应用的 bug，很难往入口上想。

### 3. 服务健康

```bash
curl -s https://mcp.atlascloud.ai/readyz -o /dev/null -w '%{http_code}\n'
```

期望 `200`。

## 回滚

```bash
kubectl -n atlas-mcp set image deploy/atlas-mcp \
  mcp=registry.atlascloud.ai/vcv-dg/atlascloud-mcp-openai-plugin:v2.6.0
kubectl -n atlas-mcp rollout status deploy/atlas-mcp --timeout=180s
```

ConfigMap 那三行和 ingress 的上限**可以留着**：旧镜像不认识那三个变量（会忽略），
ingress 放宽也不影响旧版本。只回镜像就够。

## 影响范围

**新增两个工具，不改任何现有行为。**

- 用户可以让 AI 直接上传本地图片/视频了（此前只能自己传图床给链接）
- 多了一个"列出最近任务"的只读工具
- **不影响官网、控制台、API key 调用** —— 那几条路不走 MCP
- **不影响已授权用户** —— 权限范围没变，不需要重新授权
- 生产的 Cloudflare **不用动**：已实测 `/upload/*` 直接到应用，没被 Access 拦

## 顺带一句

这次是正常走 tag 发布的：`v2.7.0` 已推，CI 自动构建出上面这个 digest。

上一版 `v2.6.0` 当时是手动构建的、没有对应的 git tag。我们不打算补打那个 tag——
补打会触发 CI 重新构建并覆盖 registry 里现有的 `v2.6.0`，而生产清单引用的是标签不是
digest，下次重建 Pod 时会悄悄拉到一个不同的镜像。从这一版起恢复规矩即可。
