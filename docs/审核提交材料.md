# Atlas Cloud MCP · 审核提交材料

对应产品提出的三项要求。**第 1 项有一个必须先修的阻塞问题，见下。**

---

## 1. 生产 MCP URL

```
https://mcp.atlascloud.ai/mcp
```

公开可访问，不在 Cloudflare Access 后面，无需内网或 VPN。

审核会扫的三个端点，实测均 `200` 且**不带任何 cookie 也能访问**：

| 端点 | 状态 | 内容 |
|---|---|---|
| `/.well-known/oauth-protected-resource` | 200 | 资源标识 + 授权服务器 |
| `/.well-known/openai-apps-challenge` | 200 | ⚠️ **见下方阻塞问题** |
| `/healthz` | 200 | 存活检查 |

资源元数据返回：

```json
{
  "resource": "https://mcp.atlascloud.ai/mcp",
  "authorization_servers": ["https://auth.atlascloud.ai"],
  "scopes_supported": ["tasks:read"],
  "bearer_methods_supported": ["header"],
  "resource_name": "Atlas Cloud MCP Server"
}
```

### ⚠️ 阻塞问题：challenge token 现在是占位符

`/.well-known/openai-apps-challenge` 当前返回：

```
9f3b7c2a1e5d8f4b6c0a2e4d6f8b0c2a4e6d8f0b2c4d6e8f0a2b4c6d8e0f2a4b
```

拆开是 `9f3b7c2a1e5d8f4b` / `6c0a2e4d6f8b0c2a` / `4e6d8f0b2c4d6e8f` / `0a2b4c6d8e0f2a4b`
—— 手编的规律串，来自部署时那份标着「占位符」的 Secret，**不是 OpenAI 发的真 token**。

域名归属验证会失败。提交前必须换成真值：

```bash
# 1. 从 OpenAI 插件门户取到真实的 challenge token
# 2. 替换 Secret 里那一个键（其余键不动）
kubectl -n atlas-mcp get secret atlascloud-openai-plugin -o json \
  | python3 -c "import json,sys,base64;d=json.load(sys.stdin);d['data']['openai-challenge-token']=base64.b64encode(b'<真实token>').decode();print(json.dumps(d))" \
  | kubectl apply -f -

# 3. 必须重启 —— secretKeyRef 注入的 env 在 Pod 启动时固化，不会热更新
kubectl -n atlas-mcp rollout restart deployment/atlas-mcp

# 4. 验证
curl -sS https://mcp.atlascloud.ai/.well-known/openai-apps-challenge
```

> 同一份 Secret 里的 `generation-confirmation-secret` 长得是同一种规律串，大概率也是占位符。
> 它不影响审核（只用于报价确认的签名），但建议一并换成 `openssl rand -hex 32` 的真随机值。

## 2. 测试用例

审核员在 Codex 里连上插件、用测试账号登录后，逐条发送即可。
**每条都写明了期望现象**，便于判断通过与否。

### 正向 5 条

| # | 输入 | 期望 | 花费 |
|---|---|---|---|
| **P1** | `列出 Atlas Cloud 上的图片生成模型` | 返回模型列表（含模型 ID、能力标签）。这是只读工具，用来确认连接与授权成功 | $0 |
| **P2** | `查一下 bytedance/seedream-v5.0-lite 这个模型的参数和价格` | 返回完整输入 schema、枚举值、默认值与定价 | $0 |
| **P3** | `用 seedream 生成一张 512x512 的图，内容：一只橘猫坐在窗台上` | **不弹确认直接生成**（报价 $0.0315，远低于 $20 阈值），图片显示在对话中，并报出实际扣费 | ~$0.03 |
| **P4** | `查一下我的 Atlas 账户余额` | 返回该登录账号自己的余额。用于确认**费用记在调用者账户上**，而非某个共享账号 | $0 |
| **P5** | `用 atlas_get_prediction 查一下刚才那个任务的结果` | 用 P3 返回的 prediction ID 查询，返回 `status: completed` 与产出 URL | $0 |

**P3 和 P4 合起来是这个插件的核心主张**：用户只在浏览器里用自己的官网账号登录一次，
不需要复制粘贴任何 API key，生成费用直接记在他自己的余额上。

### 负向 3 条

| # | 输入 | 期望 | 花费 |
|---|---|---|---|
| **N1** | `用 openai/this-model-does-not-exist 生成一张图` | 明确报错「模型不存在」，**不提交、不扣费**。模型 ID 在提交前会对活动目录校验 | $0 |
| **N2** | `用 seedream 生成图片，但不要给任何提示词` | schema 校验失败并说明缺了哪个必填字段，**不提交、不扣费** | $0 |
| **N3** | `用 bytedance/seedance-2.5/text-to-video，resolution 设 4k-esr、duration 设 25，生成一个海浪日落的视频` | **返回报价并停下等确认**（报价约 $42.59，超过 $20 阈值），同时给出一个 confirmation token。**在用户明确确认之前不产生任何费用** | $0 |

**N3 是这里最值得看的一条**：低价任务直接跑不打断用户，昂贵任务一定先报价、
一定要用户在新的一轮对话里明确同意才会提交。这条边界由服务端强制，
模型不能自行跳过，也不能把「继续」「重试」当成确认。

> N3 把模型和参数写死，是故意的。只说「生成一个视频」的话，模型可能挑到
> 1080p（报价 $8.89），低于 $20 阈值就直接提交扣费了 —— 那验的就不是确认闸门，
> 还会吃掉测试账号大半余额。写死 `4k-esr` + `duration 25` 报价才稳定在 $42.59。

> 另有一条无需账号即可验证的负向用例：不带令牌直接 `POST https://mcp.atlascloud.ai/mcp`
> 返回 `401` 并在 `WWW-Authenticate` 头里指出授权服务器地址。

## 3. 审核专用测试账号

### 必须满足

| 要求 | 说明 |
|---|---|
| **密码登录** | 官网登录页支持密码登录（也支持 Google / GitHub）。给审核账号设好密码即可 |
| **不能有 MFA / 短信 / 邮箱验证码** | 审核员收不到你们的短信和邮件。这个账号的二次验证必须关闭 |
| **不需要内网 / VPN** | `auth.atlascloud.ai` 与 `mcp.atlascloud.ai` 都在公网，无 Cloudflare Access |
| **账户余额 ≥ $5** | 测试用例只花约 $0.03，但余额为零会在报价环节被挡下，审核员会看到一个与功能无关的错误 |
| **别确认 N3 的报价** | N3 报价 $42.59，只看报价不花钱；真按了确认会因余额不足失败。用例写的是「停在报价」，到此为止即可 |

### 建议

- 单独开一个账号，别用现有员工账号——审核员的操作会进这个账号的账单和历史
- 别给它任何管理员权限，普通用户即可
- 审核期结束后停用

### 交给审核方的信息

```
MCP URL:  https://mcp.atlascloud.ai/mcp
登录地址: 浏览器会自动跳转，无需手动访问
账号:     <邮箱>
密码:     <密码>
```

登录流程：在 Codex 里首次调用工具 → 自动弹出浏览器 →
用上面的账号密码登录 → 点同意 → 自动跳回 Codex。全程无需再输入任何东西。

## 上架前还差什么（按归属分）

截至最后一次核对，生产实测状态如下。

### 我们（MCP 服务）

| 项 | 状态 |
|---|---|
| `https://mcp.atlascloud.ai/mcp` | 通。未授权 POST 返回 401 并带 `WWW-Authenticate` |
| 资源元数据 | 通。`resource` 即上面这个地址 |
| 域名验证端点 | 端点在，**值还是占位符**，等门户发真 token 后写 Secret 重启 |

### 官网生产 OIDC（`auth.atlascloud.ai`，随后端上线，不在本仓库）

| 项 | 状态 |
|---|---|
| CIMD | 已支持（`client_id_metadata_document_supported: true`） |
| `private_key_jwt` | **未声明**。ChatGPT 的 client_id 被 AS 拒，见下方对照实验；根因待对方查日志 |
| `userinfo_endpoint` | **未声明**，`/me`、`/userinfo` 均 404 |
| `email` scope / `email_verified` claim | **均无** |

> 别拿 Codex 能用当依据：Codex 的客户端文档声明的是 `none`，天然绕开了
> `private_key_jwt` 这个问题，ChatGPT 那份不是。

**对照实验**（同一个 authorize 请求，只换 `client_id`，其余参数完全一致）：

| client_id | 文档里的认证方法 | 生产 AS 的响应 |
|---|---|---|
| `chatgpt.com/oauth/client.json` | `private_key_jwt` | **401 `invalid_client`**，没走到登录页 |
| `chatgpt.com/oauth/codex/client.json` | `none` | 302 正常跳 `www.atlascloud.ai/login` |

ChatGPT 侧现在无法完成授权，这一条是实测的。

**但根因从外部判断不了。** 下面三个 client_id 返回的错误完全一样：

| client_id | 响应 |
|---|---|
| `chatgpt.com/oauth/client.json`（真文档） | 401 `invalid_client` |
| `chatgpt.com/oauth/zzz-does-not-exist.json`（不存在） | 401 `invalid_client` |
| `example.com/client.json`（非白名单主机） | 401 `invalid_client` |

错误文案没有区分度，所以分不清 AS 是「拉了文档、因内容拒绝」还是「压根没拉、
client_id 不在允许名单里」。两者修法不同，必须由 AS 侧查日志定位。

两份文档的差异也不止认证方法：`application_type`（web vs native）和
`redirect_uris`（https 回调 vs 环回地址）都不同，不能把结论直接归到
`private_key_jwt` 上。

### 待决定

资源元数据只公示 `tasks:read`，写权限走 step-up（见 `src/config.ts` 的设计注释）。
step-up 要求客户端收到 403 后主动二次授权，这是 MCP 客户端的可选行为，
没在 ChatGPT 连接器平台实测过。若担心审核期卡 403，可在 MCP 服务上设
`MCP_ADVERTISED_SCOPES=tasks:read,tasks:write,billing:read` 一次性公示三个，
不需要改代码。

## 关于 `$schema` 那个地址

门户上传 `chatgpt-app-submission.json` 时报过一次：

> must use $schema "https://developers.openai.com/apps-sdk/schemas/chatgpt-app-submission.v1.json"

这里 OpenAI 自己两边对不上，遇到了别慌：

| | 地址 |
|---|---|
| 门户校验要求 | `.../apps-sdk/schemas/chatgpt-app-submission.v1.json` |
| 该地址实际行为 | 301 跳到 `.../plugins/schemas/...` |
| 跳过去那份文档里 `$schema` 的 const | `.../plugins/schemas/...` |

也就是说发布出来的 schema 和门户校验器要的不是同一个字符串。
`docs/chatgpt-app-submission.json` 按**门户报错**来写（那才是实际挡住提交的一方），
除这一个字段外完全符合发布的 schema。

哪天门户改口要 `plugins` 那个地址，重新生成一份即可，两份内容只差这一行：

```bash
npx tsx scripts/generate-app-submission.ts docs/chatgpt-app-submission.json plugins
```

## 提交前的最后检查

```bash
# 1. challenge token 已换成真值（上面的阻塞问题）
curl -sS https://mcp.atlascloud.ai/.well-known/openai-apps-challenge

# 2. 资源元数据指向生产
curl -sS https://mcp.atlascloud.ai/.well-known/oauth-protected-resource

# 3. 未授权请求正确返回 401 + WWW-Authenticate
curl -sSI -X POST https://mcp.atlascloud.ai/mcp | grep -i www-authenticate

# 4. 用测试账号在无痕窗口走一遍完整登录，确认不需要验证码
```

第 4 条必须用**无痕窗口**：你自己的浏览器带着已登录的会话，
测出来一定是通的，看不出审核员会遇到什么。
